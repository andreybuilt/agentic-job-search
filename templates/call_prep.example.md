## Scenario-question methodologies

Pick the structure that matches the question type before you answer -- don't freestyle.

1. **Diagnostic method (for "how would you debug/solve X" questions)** -- walk it in order:
   **isolate** (narrow down where the problem lives) → **locate** (find the specific root
   cause) → **contain** (stop it from getting worse / mitigate) → **explain** (what you'd tell
   the team or customer afterward, and what you'd change to prevent recurrence).
2. **"Tell me about a time…" structure** -- Situation → Task → Action → Result, with the Result
   stated as a number or concrete outcome wherever possible, pulled only from `FACTS.md`.
3. **Success-criteria structure (for "how would you approach your first 90 days" type
   questions)** -- state what you'd learn first, what you'd ship first, and how you and your
   manager would both know it worked.
4. **Trade-off structure (for "how would you decide between X and Y" questions)** -- name the
   actual constraint that makes it a real trade-off, not a false choice.
5. **Clarifying-question opener (for ambiguous prompts)** -- ask one scoping question before
   answering, so you're not solving the wrong problem.

## Scripted line for a sensitive gap (layoff / departure)

> "That role ended as part of a broader reduction in force at [Company] -- it wasn't
> performance-related, and the team I worked with would tell you the same. I used the time to
> [sharpen a specific skill / ship a personal project / interview deliberately], and I'm glad to
> talk through what I learned from it."

Keep it neutral, factual, brief, and move on -- don't over-explain or editorialize.

## Reminder

**Never disparage a named past employer**, manager, or team -- even if the honest story isn't
flattering to them. Describe situations, decisions, and outcomes; leave out blame.
